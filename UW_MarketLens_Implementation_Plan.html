UW MarketLens

AI-Powered Prediction Market Reliability Platform
University of Washington · Spring 2025 · 3-Week Build · Team of 3 · Live on Render

This plan breaks the project into self-contained sections. Sections are designed so several can be built at the same time and so any team member can pick up any section — we rotate through parts to learn the whole stack rather than splitting into silos.

Working principle. Agree on the shared JSON schemas first (Section 0). After that, every section is built against mock data, so nobody is blocked waiting on a teammate. Real wiring happens at integration in Week 2.
Build status. The end-to-end mock slice is shipped and deployed live on Render (static frontend + FastAPI backend, env-driven URLs, CI config in render.yaml). Done: S0 schemas, S6 citation, S7 composite (placeholder weighting), S8 backend shell with score / snapshot / library / citation / admin / dynamic-OG-card endpoints, S9 frontend (multi-page: lookup, verdict report, snapshot permalink, compare, library, admin, about) plus Markdown export, trust disclosures, accessibility pass and route code-splitting, and dark mode toggle with persisted preference and system-theme fallback. In progress: S1 Polymarket ingestion (real data behind the mock boundary). Pending: S2–S5 real models and S11 user testing.

DMethodological Weaknesses & Mitigations

Honest appraisal of where the methodology is weak, and how we address each within the 3-week scope. Most fixes are framing/methodology choices, not extra code — and acknowledged limits score better than hidden ones.

WeaknessMitigation (in scope)
0–100 composite score = false precision. Blending an unvalidated anomaly score + LLM verdict + liquidity heuristics into one number looks authoritative but isn't calibrated to any real outcome. Lead with the HIGH/MEDIUM/LOW band; show the number only as secondary. Always render the decomposed reasons[]. Publish the weighting rubric — and state plainly that weights are currently equal / uncalibrated (the build composites by an equal-weighted mean of mock subscores; the rubric must not imply tuned weights). ~1 day, mostly S9 + a methodology note.
Anomaly detection has no ground truth. Isolation Forest finds statistical outliers ≠ manipulation. Evaluating only on self-injected synthetic anomalies is circular. Add a small real-data sanity set (~10–15 documented-controversy vs. ~10–15 mundane) and show the detector fires more on the known-bad set. Explicit fallback: this is coupled to the S1 API-access risk and may slip — if trade-history retrieval is thin, ship synthetic-only plus a stated limitation rather than blocking S3. Reframe output as "unusual activity worth a human look," a flag, not a scored input, if the real-data check is weak.
Thin validation (n=30). Too small to support accuracy claims for both the LLM checker and anomaly model. Report confidence intervals, not point estimates ("80%, 95% CI ±14%, n=30"); add inter-rater agreement (≥2 labelers, Cohen's κ); stratify the 30 (easy / ambiguous / thin-liquidity); pre-register the rubric. Consequence: a ±14% interval means "≥80%" can't be a pass/fail gate — reword the Week-2 milestone from "achieve ≥80% agreement" to "report agreement with CI" so §4 and §D don't contradict.
Unclear audience. Active traders already see liquidity/volume natively — what's the edge? Position explicitly as a triage & citation tool for non-expert / academic users (library-by-department + reliability- flagged APA/MLA citation already are this). State the mission plainly in /about (S11). Zero code.
Meta-point. Three of the four reduce to the same move: present what we actually have, with explicit uncertainty, and demote anything we can't back up. Reviewers grade calibration and self-awareness, not bravado. Only the anomaly real-data set needs genuinely new work, and it has an explicit synthetic-only fallback so it can't block the deliverable.

ES3 Eval: Honest Findings & Real-System Gaps

After hardening the anomaly module (engineered features, RobustScaler, per-market stream pipeline, multi-feature coordinated_manip pattern, operating-point grid, Precision@K, ROC/PR-AUC, SHAP attribution, bagged ensemble, drift smoke check, 30 pytest cases), the v3 multi-seed run produced an honest, calibrated picture rather than a flattering headline number.

Reading: IF earns its place precisely where the proposal expected it to — when the manipulation signature is correlated across features. On single-feature spikes, a properly chosen z-score is by construction near-optimal and IF cannot beat it. This pattern is consistent with published trade-surveillance literature: anomaly models add value over rule packs on novel multi-feature combinations, not on textbook single-axis red flags.

Methodological caveat we don't hide

Our row-level injectors perturb every test row, which means a per-market z-score baseline sees a uniform shift and has no within-market deviation to flag (ROC ≈ 0.500). On the sparse episodic coordinated_manip pattern (the realistic injection density) the per-market relative baselines do show signal. This is itself a finding: injection density matters, and our headline comparison would shift if we matched real surveillance's sparse-anomaly setting throughout.

What a production-grade surveillance system has that we don't (deferred, named)

GapWhy deferred
Order-book / order-flow features. Top-of-book imbalance, depth at K levels, quote-flicker rate, order-to-trade ratio (the single most cited spoofing signature), cancel-rate bursts. Polymarket's public CLOB endpoints do not expose the depth-history granularity these features require.
Real labeled cases. Historical confirmed manipulation incidents to evaluate against, instead of self-injection (which matches the model's inductive biases by construction). No public Polymarket equivalent of a CFTC/SEC fine ledger. Phase A ships the plumbing — pre-registered rubric (v1), an end-to-end labeled-eval script, bootstrap-CI ROC-AUC, and a low_n_warning flag — but the case list itself is empty until the team verifies real entries against the rubric. No labeled number is quoted in this plan because none has been produced from verified data yet.
Trader-network / wallet-address graph features. Repeat-counterparty ratio, connected-component analysis, USDC funding-chain clustering, sybil heuristics. Phase A wires four graph features (net_unique_wallets, net_top_trader_hhi, net_repeat_counterparty, net_largest_component) end-to-end: synthetic training, the live POST /api/live/score route, and the labeled-eval scorer all see them. The synthetic sybil_ring injector exists to verify the code path runs, not as evidence of detection skill — it perturbs the same columns the new features target, so any AUC it produces is circular by construction. Real lift remains unmeasured pending a cached real-market corpus.
Multi-scale temporal context. Simultaneous 1s/1m/5m/1h rolling windows + change-point detection (CUSUM, BOCPD) against each market's own history. Our streams have per-market relative features (a partial proxy); a full multi-scale stack needs real time-stamped trades from S1.
Time-cross-validation on real data (train month T, test T+1) + drift monitoring (PSI/KS divergence per feature, rolling re-fits, shadow deploys). We ship a synthetic drift smoke test (AUC under a shifted distribution). True time-CV is deferred to post-S1.
Supervised tier + human review feedback loop. Production stacks pair unsupervised IF with a supervised model on triaged alert outcomes; analyst feedback retrains. No labeled alerts; no analyst pool. The closest UW analog (the LLM resolution checker, S4) operates downstream of scoring, not on alerts.
Realistic low-FPR operating point. Real surveillance targets FPR ≤ 0.1–1% with Precision@K as the primary metric. Recall at 20% FPR is a tutorial number. We now report the full grid (R@0.5%, R@1%, R@5%, R@20%) and Precision@{10,50,100}; the headline-friendly 20% figure is no longer the only one we surface.
Bottom line — honest rating ≈ 4.5/10. The headline synthetic result (model wins on the multi-feature pattern, loses on single-feature spikes) is the shape a properly framed synthetic eval should produce. The Phase A plumbing — trader-network features through training and scoring, microstructure proxies, the labeled-eval pipeline with bootstrap CIs — is real and runs end-to-end. But the model is still trained on 100% synthetic data with hand-picked feature distributions, the sybil_ring injector is circular (perturbs the same columns the new features target), and the labeled-cases file is empty pending team-verified entries. No real-market AUC has been produced. The synthetic eval artifact at backend/app/anomaly/last_eval.json carries the verifiable numbers; app/anomaly/MODEL_STATUS.md states the honest current rating; the path from 4.5/10 to genuine 6/10 (and beyond) is documented in a separate local file: UW_MarketLens_Push_To_Six.html. Stopping S1 and the Isolation Forest work here was a deliberate choice against shipping unverifiable claims.
