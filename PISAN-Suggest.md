## Suggested Improvements & New Features

- The `mock.py` swap-out is documented as temporary but is still the default for `/api/score` (`backend/app/routes/score.py:22`). Either delete the mock route and route everything through `/api/live/score`, or have the frontend default to live and only use mock as an explicit fallback.
- Pin `typescript`, `vite`, and other dev-deps in `frontend/package.json` to versions that actually exist (TypeScript 6 and Vite 8 are not released as of 2026-05-26). A fresh `npm ci` may fail or pull unexpected versions.
- The shared email `bob452305@gmail.com` across `Rogagoja`, `rogagoja`, and `Leonikot` GitHub authors will confuse `git shortlog`. Standardize on one identity per teammate (`git config user.name/email`) before submission so peer review evidence is clean.
- `live.py:1-26` is a great docstring; consider extracting the same level of header into `mock.py` so a reader landing on the route sees the contract immediately.
- Add a top-level `Makefile` or `justfile` with `make dev`, `make test`, `make deploy-preview` so a grader can run everything from one command instead of two terminals.
- `backend/requirements.txt` includes `shap==0.46.0` but I see no SHAP usage in the routes. If you're not using it, drop it (it's a heavy install on a free-tier dyno).
- Consider a GitHub Actions workflow that runs `pytest` on push so the test suite is visibly green. There is currently no `.github/workflows/` directory.

### UI / UX Improvements

- Add a small "Live | Mock" indicator on every page (not just nav). Right now `MarketScore.source` is in the schema (`backend/app/schemas.py:114`) but a casual user can't easily tell whether the report they're looking at is real or mock.
- The home page only shows recent lookups from `localStorage`; add a "Featured UW-relevant markets" carousel sourced from the library so a first-time visitor can click into a real example without having to find a Polymarket URL.
- Empty-state copy for the Library and Admin pages would help when those endpoints return no data (e.g., when running disconnected).
- The hero copy says "we issue a stable, dated citation you can defend in a paper" — back this up with a one-click "Open sample report" button next to the URL input so a new visitor doesn't have to know what a Polymarket URL looks like.
- Add a 404 page that links back to home (`App.tsx:105-112` currently just shows centered text).

### New Features

- **UW Library citation export hook**: the existing `Citation` model (`backend/app/schemas.py:62`) already produces APA/MLA/BibTeX. Add a "Send to Zotero" or "Copy as RIS" action to make this concretely useful for UW researchers.

- **CSV download of the library** so a research-methods instructor can use it as a data set in a class assignment — a small feature that materially strengthens the UW-community angle.

### AI Integration Enhancements

- **Evaluate against the labeled set you've already built**. `backend/app/anomaly/data/labeled_cases.yaml` and `scripts/eval_on_labeled.py` are in place; the `last_labeled_eval.json` is the missing artifact. Filling out the AboutPage "evaluation results" table with real numbers (recall @ 20% FPR, AUC) would be the single biggest credibility win for the AI rubric and turn the project from "promising scaffolding" into "evaluated system."
- The detector is trained on synthetic streams (`scoring.py:59-66`). Even a small (~20-50) corpus of real Polymarket markets used as a *training* set rather than a *labeled eval* set would push the project from "isolation forest on synthetic data" into "isolation forest on real markets."
- The LLM-as-judge prompt (`resolution.py:49-67`) currently asks for a single verdict. Consider chain-of-thought or self-consistency (sample 3 verdicts, take majority) — easy upgrade given the structured output schema is already there.
- Add a confidence calibration check: do high-confidence verdicts actually correlate with verified resolutions? With the labeled corpus this is a 30-line script and a chart in the About page.
- Consider adding a SHAP explanation panel for the anomaly detector (you already imported `shap`); per-window feature attributions would close the loop on the "the why, not the number" pillar.
